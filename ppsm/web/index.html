Guide

A PPSM register lists every service an enclave uses: protocol, port, system, boundary crossed, the rule that permits it, and why it exists. This tool collects that from hosts, firewalls, switches, scanners and DNS, cross-references it, and writes the eMASS import template. Everything runs on this machine.

Workflow

  1. Setup. Fill in the system header. Drop the collection folder on the ingest box.
  2. Register. Review the rows. Set Boundary on every row; it drives the diagram and the export. Use filters and bulk-apply for large sets.
  3. Review. Fill In derives what the data can prove. Run Checks lists what a reviewer would send back. Rule Coverage compares observed flows with the imported ruleset.
  4. Endpoints. Load a host inventory and name anything still unidentified. An address is not a system.
  5. Export. eMASS Import (allow.xlsx) for submission. Work is autosaved; Save Session keeps a copy you can move.

Collecting

  • collectors/ppsm-collect.ps1 on Windows, collectors/ppsm-collect.sh on Linux, or collectors/ppsm.yml with Ansible for a fleet. Each writes one results folder.
  • Firewall: show conn all, show running-config access-list and object-group, or FMC report exports.
  • Switches: show flow monitor <name> cache format csv, or a NetFlow analyser's top-conversations report.
  • ACAS: export the scan as .nessus.

What is read

Hostsnetstat, ss, Get-NetTCPConnection, collector output, Windows Firewall log and rules
Firewallshow conn, access-list and object-group, FMC reports, FMC policy (PDF or CSV), ASA syslog, iptables, Palo Alto
NetworkNetFlow cache, top conversations, Zeek conn.log, pcap and pcapng, tcpdump, pktmon
ScansNessus and ACAS, nmap XML
NamesDNS zones forward and reverse, Windows DNS exports, AD and CMDB exports, hosts files, DHCP leases, ARP
ContainersCSV, Excel, text-based PDF, plain text. Files are identified by content, not name.

Boundaries

Traffic that stays inside the enclave is Internal and carries no B number. B13 and B14 are set where one end is outside your ranges. DISN crossings (B1 to B8, B15) are never set automatically because host and firewall data cannot prove them. Set those yourself.

Where work is kept

The session is written to the data folder shown when the app starts, after every change. Nothing is sent anywhere. New Session on the Export page discards it. The Self-Test button runs the engine's checks in this browser.
